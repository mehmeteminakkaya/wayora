# Download a trip as a calendar (.ics) file

## Description
Serves W-36 (add my route to my phone or computer calendar). This task adds an API endpoint that
returns one trip's activities as an iCalendar file that Google Calendar, Apple Calendar and Outlook
can import. Out of scope: a download button in the web app (follow-up task), subscribing to a live
calendar URL, time zones other than the trip's local wall-clock time, and reminders/alarms.

## Specs
- `GET /api/trips/:id/calendar.ics` in `api/src/routes/trips.ts`, behind the existing session auth.
- Without a session it returns HTTP 401. For an unknown trip id or another user's trip it returns
  HTTP 404 with the same error body as `GET /api/trips/:id`.
- On success it returns HTTP 200 with `Content-Type: text/calendar; charset=utf-8` and
  `Content-Disposition: attachment; filename="wayora-<destination>-<startDate>.ics"`, where
  `<destination>` is lower-case ASCII (Turkish letters transliterated, other characters → `-`) and
  `<startDate>` is `YYYY-MM-DD`. Example: `wayora-paris-2026-11-10.ics`.
- The body is an RFC 5545 calendar: `BEGIN:VCALENDAR`, `VERSION:2.0`, `PRODID:-//Wayora//Trip//TR`,
  then one `VEVENT` per activity in day order and activity order, then `END:VCALENDAR`. Every line
  ends with CRLF (`\r\n`).
- Each `VEVENT` has `UID:<activity id>@wayora`, `DTSTAMP` (UTC, `YYYYMMDDTHHMMSSZ`), `SUMMARY` (the
  activity title) and, when the activity has a place address, `LOCATION`.
- An activity with `startTime` gets a timed event on its day's date, as floating local time:
  `DTSTART:20261110T090000`. `DTEND` uses `endTime`; without `endTime` it is one hour after the start.
- An activity without `startTime` gets an all-day event: `DTSTART;VALUE=DATE:20261110` and
  `DTEND;VALUE=DATE:20261111`.
- Text values escape `\`, `;`, `,` and newlines as RFC 5545 requires (`\`, `\;`, `\,`, `\n`).
- A trip with no activities returns a valid calendar with zero `VEVENT`s.

## Requirements
- Read the trip with the existing owner-scoped query (`userId` in the `where`); no schema change.
- Build the file in a small pure helper (`api/src/lib/ics.ts`) so it can be unit-tested; no new
  runtime dependency.
- Existing trip routes and tests keep passing.

## Acceptance criteria
1. Without a session the endpoint returns 401; for another user's trip it returns 404.
2. The owner gets 200 with `text/calendar` content type and an attachment file name of the form
   `wayora-<destination>-<YYYY-MM-DD>.ics`.
3. The calendar contains exactly one `VEVENT` per activity, and a timed activity has `DTSTART`/`DTEND`
   on its day's date with its start and end times.
4. An activity without a start time becomes an all-day event on its day.
5. Commas, semicolons and line breaks in an activity title are escaped, and every line ends with CRLF.
