# Exclude finished trips from Yol Arkadaşları matches

## Description
Serves W-35 (match only with upcoming or ongoing trips). Today `GET /api/social/matches` scores
every trip in the database, so a trip that already ended (for example 6–8 Kasım, seen on production
on 26 Kasım) is still offered as a "3 gün ortak" match. This task makes the matcher ignore trips
whose last day is before today, on both sides. Out of scope: hiding past trips anywhere else in the
UI (Rotalarım already has a "Geçmiş" tab), changing the score formula, and pagination.

## Specs
- `scoreCandidate(myTrips, candidate, context, today?)` in `api/src/services/social.ts` takes an
  optional `today: Date` (default: the current time). Only the UTC calendar day of `today` matters.
- A trip is **finished** when the UTC day of its `endDate` is before the UTC day of `today`.
- Finished trips are skipped on both sides: a candidate's finished trip never produces a match, and
  the user's own finished trip never produces a match.
- A trip whose `endDate` is today, or that has not started yet, is not finished and is matched as
  before (same city + at least one overlapping day).
- When every overlapping pair contains a finished trip, `scoreCandidate` returns `null`, so the
  candidate is not listed by `GET /api/social/matches`.
- For trips that are not finished, the score, `overlapDays` and `reasons` are unchanged.
- `GET /api/social/matches` calls `scoreCandidate` with the request time as `today`.

## Requirements
- Change only the matching service and the call site in `api/src/routes/social.ts`; no database
  schema change and no new dependency.
- Date comparison is by UTC calendar day, consistent with `overlapDays`.
- Existing social tests keep passing; tests that use fixed November 2026 trips pass an explicit
  `today` so they do not depend on the machine clock.

## Acceptance criteria
1. A candidate trip that ended before today is not matched, even when it shares the city and dates
   with the user's trip.
2. The user's own trip that ended before today does not produce a match.
3. A trip whose last day is today is still matched.
4. For upcoming overlapping trips, the result (score, overlap days, reasons) is the same as before
   this change.
